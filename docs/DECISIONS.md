# Decisions

One line per significant technical decision: `choice over alternative: reason`.

- Python core + FastAPI + React over TS monolith port: engine must own Python AST; UI is a separate surface on a stable JSON contract.
- CLI-first with optional workspace UI over UI-required product: CI and local hooks need a headless binary; history/inspection should not gate verification.
- SQLite run store over “only stdout”: enables UI history and reopen without inventing a cloud.
- Shared pydantic models for CLI JSON and API over duplicate TypeScript types as source of truth: generate or mirror TS types from OpenAPI if needed; Python owns the schema.
- `ast` + import resolution over regex-only imports: catches hallucinated modules with acceptable complexity for v1.
- Scope as low-confidence heuristic over LLM-in-pass-1: keep Pass 1 free/fast; intent stays Pass 2.
- Default agent model `claude-opus-5-5` over smaller defaults: intent classification is the product’s hard semantic job; make override easy for cost.
- Calm CLAUDE.md / AGENTS.md (no CRITICAL spam) for Opus 5.5: stronger models overtrigger on aggressive harness language.
- Local git diffs require no GitHub auth over GitHub-centric design: auth only when a later phase fetches remote PRs.
- Verdict rule ported verbatim from the TS reference over reinventing thresholds: any `error` → fail, any finding or agent flag → review; keeps exit codes comparable across both implementations.
- Agent findings pinned to `warn` over letting the model pick severity: Pass 2 may demand review but must never claim objective failure.
- camelCase wire keys via pydantic alias generator over snake_case JSON: the React client is a first-class consumer and the schema is frozen at v1.
- `default_factory` for all model defaults over bare instances: a shared `ReportMeta()` froze `createdAt` at import time.
- Hand-rolled diff parser over `unidiff`/GitPython: stdlib-only, and we need git's rename and binary detection anyway.
- Imports check resolves against the *target* repo's discovered environment over vouch's own: resolving against vouch's `site-packages` would flag every real dependency of the project under review.
- Python 3.14 verified for local dev with `requires-python = ">=3.12"` and CI on 3.12/3.13: full stack (pydantic 2.14, FastAPI 0.143, anthropic 1.13) installs clean, so no interpreter pin needed.
- Containerised API mounts the target repo read-only over a writable bind: enforces the never-mutate invariant at the filesystem layer, not just in code.
- Empty-body detection via AST over regex: in Python `pass` and `...` are correct in abstract methods, `@overload`, Protocols, and `.pyi` stubs, and only the AST has the context to tell a stub from a declaration.
- Comment markers matched outside quoted spans over anywhere in the line: a comment that quotes "TODO" is documenting it, not declaring it (dogfooded, `docs/CAUGHT.md`).
- Imports in `try/except ImportError` exempt over flagging every unresolved name: an import allowed to fail is an optional dependency (dogfooded, `docs/CAUGHT.md`).
- Imports check stays silent on third-party names when no environment was discovered over guessing: a false "hallucinated import" on a real dependency would destroy trust in the headline check.
- Python keywords (`import`, `self`, `def`, `return`) treated as scope stopwords: they appear in nearly every Python file, so counting them as signal would rescue every file from scope-drift.
- Assertion counting by net delta over AST body comparison: a refactor that moves assertions nets to zero and stays silent, so only real loss flags.
- Findings sorted by severity then file then line in the pipeline over check-registration order: the terminal report should lead with what matters most.
- Anthropic client injected into `run_agent` over constructed internally: the loop is then fully testable offline with a scripted fake, and the SDK stays an optional dependency.
- Agent client duck-typed via `Protocol` over importing SDK types: nothing in the loop requires `anthropic` to be installed.
- Tool budget enforced by withdrawing the tools from the request over trusting the model to stop: removing the capability is what actually forces a verdict.
- Verdict classifications reconciled against the hunks we sent over trusting the model's file list: a fabricated path in the report would be worse than a missing one; falls back to file-only matching when ranges drift.
- Model-emitted findings validated against the whole agentic taxonomy over just the emittable subset: a valid-but-derived code degrades to a dropped finding rather than failing the parse of an otherwise good verdict.
- Sibling-module resolution via `sibling_modules` over adding `tests/` as a source root: Python and pytest both put a file's own directory on `sys.path`, which is a per-directory fact, not a project-wide one (dogfooded, `docs/CAUGHT.md`).
- Stdlib `sqlite3` over SQLAlchemy for the run store: the report is already a versioned JSON document and there is one table with one query shape, so an ORM buys nothing and `sqlalchemy` left the `api` extra entirely.
- Report stored whole as JSON with verdict/counts/branch/commit duplicated into columns over normalising findings into tables: the list view then needs no parsing, and a schema-version bump doesn't require a migration to keep reading old runs.
- `check_same_thread=False` plus an explicit lock over thread-local connections: FastAPI runs sync handlers in a threadpool, and the file-backed path already opens a connection per operation, so only the long-lived in-memory connection needs guarding.
- Store injected via FastAPI `Depends` with an `Annotated` alias over a module-level singleton: tests override it through `dependency_overrides` without patching globals, and the alias keeps ruff's B008 satisfied.
- API persists every review but the CLI only on `--save` or a configured `VOUCH_DB` over always persisting: a CI job should not accumulate state nobody reads.
- Store failures warn and preserve the exit code over aborting the run: persistence is a convenience for the UI and must never change a verdict CI depends on.
- `task.source = "api"` and `prompt=False` on the HTTP path over reusing CLI task resolution: a server must never block on a TTY prompt or silently judge a guessed transcript task.
- OpenAPI asserted against the SPEC's route/field table in tests over trusting review: the schema is the UI's contract, and drift is otherwise invisible until the frontend breaks.
- A ~40-line stdlib `.env` reader over the `python-dotenv` dependency: vouch needs one variable from a file, and the full dotenv feature set (interpolation, cascades, multi-line values) is surface area with no user behind it.
- `.env` never overrides a real environment variable, including an exported-but-empty one: an explicit shell export is a deliberate choice and a file on disk should not silently win in CI.
- `changes` (the parsed diff) added to the report over fetching the diff separately for the UI: a stored run must stay inspectable after the working tree moves on, which is exactly what reopening history requires. Additive, so the schema version holds at 1.
- `Hunk.range` is the single definition of a hunk's label, with `hunk_range_label` delegating to it, over two near-identical formatters: the agent echoes the label back and the UI joins classifications onto `changes` with it, so any divergence silently drops classification tags (which it already did for deleted, binary and zero-line hunks).
- The range format is pinned by `tests/contract/hunk-ranges.json`, asserted from both pytest and vitest, over trusting two implementations to stay in step: the failure mode is invisible in the UI, so it needs a test that fails loudly in CI.
- Vite dev-server proxy for each real API route (`/health`, `/reviews`, `/prompts`, `/openapi.json`), unrewritten, over absolute URLs to port 8741: the client only ever uses relative paths, so a production build can be served from FastAPI itself without a code change. CORS stays for direct-origin use.
- Frontend port 8742 over Vite's default 5173: it sits next to the API's 8741 and avoids the usual dev-server collisions.
- Findings are locatable only when the diff actually contains their file over whenever a file is set: `request-unfulfilled` legitimately points at a file nobody touched, and a click that silently does nothing is worse than a disabled button.
- Hand-written CSS over a component library or Tailwind: the workspace is three panels and a form, and a dependency would outweigh the markup it saves.
- Credentials withheld from Pass 2 by filename over trusting the user to keep secrets out of the working tree: untracked files are synthesized as hunks, so an uncommitted `.env` was being rendered into the prompt verbatim (found by running the live agent on a scratch repo — see `docs/CAUGHT.md`).
- Secret files are still classified, just by path and line count over being dropped from the diff: an unrequested `.env` is precisely the kind of change vouch should flag, so hiding it would trade one failure for another.
- `read_file` refuses credentials files and `search` drops matches from them, over gating only the prompt: the agent loop has read tools, and a grep result carries the matching line, so the prompt was only one of three ways out.
- `.env.example` and `*.sample` stay readable over matching the `.env` prefix: they are documentation, and withholding them teaches the model nothing while costing a real signal.
- Agent-returned ranges normalized on parse over trusting the echo: the model returned `[1-5]` with the prompt's brackets in live testing, which cost findings their line numbers and would have silently dropped classification tags in the UI (see `docs/CAUGHT.md`).
- Hunks headed `range=1-5` rather than `[1-5]` in the prompt over relying on the normalizer alone: the cheapest fix is not inviting the mistake, but the normalizer stays because a model can ignore instructions.
- CLI flags asserted by introspecting the Click command over scraping `--help`: Typer renders help through Rich, which wraps to the terminal width, so the rendered-text assertion passed locally and failed on every CI run for five commits.
- The task is read from the agent's own transcript over always asking the user to retype it: you already typed it once, and retyping invites you to describe what the diff does rather than what you asked for — which is the one comparison vouch exists to make.
- Transcripts are read from both Cursor CLI and Claude Code over Claude Code only (the original Phase 3 plan): the formats differ only in path encoding and record shape, and this project is itself developed in Cursor CLI, so supporting one and not the other would have shipped an untested code path.
- A transcript task is confirmed on a TTY and labelled `transcript` in the report, over being used silently: it is inferred, and a verdict against a task the user never chose is worse than no verdict.
- Acknowledgements ("ok", "yh go on", "thanks") are filtered from transcript prompts over taking the literal last user message: short replies to the agent are the most recent thing typed but carry no intent, and they are what you would get most of the time.
- Transcript parsing is total — malformed JSON, a renamed directory or a format change all yield "no prompts" — over raising: these are undocumented formats owned by other tools, and a convenience feature must not be able to fail a run.
- The API exposes `GET /prompts` and the UI offers a picker, over the server guessing a task for `POST /reviews`: in a browser there is no TTY to confirm on, so the choice moves to the user instead of disappearing.
- Demo history is seeded by running the real pipeline over scripted diffs (`scripts/seed_demo.py`) over inserting fabricated rows: the workspace's whole value is showing genuine classifications and costs, and a hand-written row would be the one thing in the UI that is not real.
- The Vite proxy list is asserted against the API's OpenAPI paths in pytest, over trusting it to be updated by hand: `/prompts` shipped unproxied, so the prompt picker worked on 8741 and silently hid itself on 8742, where Vite answers unknown paths with `index.html`.
